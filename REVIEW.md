# REVIEW.md

Defects found in the starter `app/main.py` (helpers and endpoints), and how each one was fixed.

| #   | Where (function / line)                 | What is wrong                                                                                                                                                                                                                                                                                                   | How you'd notice it (test, input, or symptom)                                                                                                       | How I fixed it                                                                                                                                                         |
| --- | --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `client = MongoClient(...)`             | Created without `tz_aware=True`, so every datetime read from MongoDB is naive (no time zone). There is also no server-selection timeout, so a dead MongoDB makes requests hang.                                                                                                                                 | `compute_overtime` subtracts an aware IST time from a naive stored time and raises `TypeError`; stored times cannot be told apart from local times. | `tz_aware=True` (everything is UTC-aware) and `serverSelectionTimeoutMS=5000`.                                                                                         |
| 2   | `health()`                              | Always returns `ok` and never touches MongoDB.                                                                                                                                                                                                                                                                  | Stop the MongoDB container and call `/health`: it still answers 200.                                                                                | It pings MongoDB; any `PyMongoError` gives 503.                                                                                                                        |
| 3   | `compute_late_minutes`                  | Builds the shift start with `punch_in.replace(hour=..., minute=...)`, so it uses the server's local zone and the punch-in's own day (not IST, and wrong for overnight shifts). It converts with `int(seconds / 60)` and tests `> 10`, so 09:40:01 (601 s) becomes 10 and counts as on time.                     | Punch in at 09:40:01 against a 09:30 shift: `late_minutes` is 0 instead of 10. Run the server in another time zone and the results change.          | `shift_bounds` builds the exact IST start for the attendance date. A punch is late only if the gap is more than 600 seconds, and the minutes are `seconds // 60`.      |
| 4   | `compute_work_hours`                    | Python `round()` on a float rounds half-to-even and carries float noise, not half-up as rule R4 says.                                                                                                                                                                                                           | A value that lands exactly on x.xx5, such as 2.675 hours, is rounded down.                                                                          | `Decimal` arithmetic with `ROUND_HALF_UP`, on whole seconds.                                                                                                           |
| 5   | `compute_overtime`                      | No 30-minute minimum (any minute counts). It uses the shift end on the punch-in's date, so overnight shifts give 0 or negative overtime. `tzinfo=IST` is attached to one side only, so subtracting a naive `punch_out` raises `TypeError`.                                                                      | Punch out 10 minutes after shift end: overtime 10 instead of 0. Punch out of an overnight shift: a crash or wrong overtime.                         | `shift_bounds` returns the real end (the next day for overnight shifts), all datetimes are aware, and overtime counts only when it is at least 30 whole minutes.       |
| 6   | `EmployeeIn`                            | No validation at all: any `emp_code`, any email, free-text shift times and `joined_on`, equal start and end, no length limits.                                                                                                                                                                                  | `POST /employees` with `{"emp_code": "x", "email": "nope", "joined_on": "2026-02-31"}` is accepted and stored.                                      | Pydantic patterns for `emp_code`, email and `HH:MM`, a real-date check for `joined_on`, `shift_start` must differ from `shift_end`, and length limits.                 |
| 7   | `create_employee`                       | The duplicate check is find-then-insert, so two simultaneous requests can both pass (there is no unique index). `created_at` uses the local, naive `datetime.now()` and is returned as a raw datetime instead of epoch milliseconds.                                                                            | Two parallel POSTs with the same code create two employees. `created_at` comes back as an ISO string.                                               | A unique index on `emp_code` plus catching `DuplicateKeyError` for the 409. UTC `now_dt()` for the time, and `employee_out` returns milliseconds.                      |
| 8   | `list_employees`                        | `skip = page * page_size` skips the first page. `total` counts all employees and ignores the department filter. There is no sort, so paging order is undefined, and `page` / `page_size` have no limits.                                                                                                        | `GET /employees?page=1` returns an empty list while `total` is 6. `?department=X` shows the total of all employees. `page_size=100000` is accepted. | `skip = (page - 1) * page_size`; `count_documents` uses the same filter; sorted by `emp_code`; `page >= 1` and `1 <= page_size <= 100`.                                |
| 9   | `punch_in` (employee lookup)            | `find_one` can return `None`, and the code then reads `emp["shift_start"]`, which raises `TypeError` and gives a 500.                                                                                                                                                                                           | `POST /attendance/punch-in` for `EMP9999` returns 500.                                                                                              | It returns 404 `employee not found`.                                                                                                                                   |
| 10  | `PunchInIn` and the timestamp           | `status` is any string (ABSENT, LEAVE and nonsense are accepted). `punched_at` is unchecked (seconds, floats and negatives are accepted) and `if body.punched_at` treats 0 as missing. `datetime.fromtimestamp(ms / 1000)` uses the server's zone and keeps fractions of a second.                              | `status: "ABSENT"` is stored with a punch time. A `punched_at` in seconds gives a date in 1970.                                                     | `status` is limited to PRESENT / WFH / ON_DUTY. `punched_at` is a strict integer in a millisecond range (otherwise 422). `ms_to_dt` returns UTC, cut to whole seconds. |
| 11  | `punch_in` (attendance date)            | The date comes from `ts.date()` in the server's zone, not IST, and ignores rule R1 (an overnight shift belongs to the day it started).                                                                                                                                                                          | A punch-in at 02:00 IST on a 22:00-06:00 shift is dated the wrong day.                                                                              | `attendance_date` converts to IST and applies the overnight rule.                                                                                                      |
| 12  | `punch_in` (duplicate check)            | The same find-then-insert race: two identical requests can both succeed.                                                                                                                                                                                                                                        | Fire 12 identical punch-ins at once and more than one gets 201.                                                                                     | A unique index on `(emp_code, date)` and `DuplicateKeyError` to 409, so exactly one request wins.                                                                      |
| 13  | `punch_in` and `list_attendance` output | Responses include `id` (the ObjectId as text) and times as datetime objects, but the contract has no internal id and wants epoch milliseconds. Older records without `history` / `half_day` are returned as they are.                                                                                           | The response contains `"id": "6..."` and ISO date strings.                                                                                          | `attendance_out` drops `_id`, converts times to milliseconds, and applies defaults (`history` empty, `half_day` false, counters 0).                                    |
| 14  | `list_attendance`                       | Loads every matching document into Python, sorts there and slices there (`total = len(docs)`), which is slow and memory-hungry at 100,000 records. It sorts only by date, so ties come in arbitrary order. `date_from` after `date_to`, bad dates, an unknown `status` and a huge `page_size` are all accepted. | Slow with a large collection. `date_from=2026-07-10&date_to=2026-07-01` returns 200 with an empty list.                                             | MongoDB does the sort (date desc, emp_code asc), skip, limit and `count_documents`. Date and status validators, and 422 when `date_from > date_to`.                    |
| 15  | indexes (none)                          | The starter creates no indexes, so every query is a full collection scan and nothing enforces uniqueness.                                                                                                                                                                                                       | The explain output shows `COLLSCAN`.                                                                                                                | `ensure_indexes()` runs at startup (see DECISIONS.md), and queries use hints so plans show `IXSCAN`.                                                                   |
| 16  | all endpoints (MongoDB outage)          | Any database error becomes a 500, and with no timeout a request can hang.                                                                                                                                                                                                                                       | Stop MongoDB and call any endpoint.                                                                                                                 | A global handler turns `PyMongoError` into 503, and the 5 second selection timeout stops hanging.                                                                      |
| 17  | missing endpoints                       | `punch-out`, `PATCH /attendance/{emp_code}/{date}`, the four analytics endpoints and the explain endpoint were only TODO comments.                                                                                                                                                                              | Calling them returns 404.                                                                                                                           | Implemented, with the business rules R1 - R10.                                                                                                                         |

## Looked at and decided it was NOT a defect

- `load_dotenv()` does not override real environment variables. That is what is wanted: a real `MONGO_URI` wins over a local `.env`.
- The fallback `mongodb://localhost:27017` and `attendance_db` are only defaults for local development; real values come from the environment.
- `status_code=201` on creation and a 409 for a duplicate `emp_code` match the contract. Only the way the duplicate was detected was wrong (item 7).
- Hiding `_id` with the projection `{"_id": 0}` in `list_employees` is the right approach, and `emp_code` (not `_id`) is the identifier, as the data model says.
